## 1. Миссия и принятый принцип

Создаём персональную веб-платформу развития знаний, критического и стратегического мышления, запоминания и практических навыков. Сайт нужен прежде всего владельцу и тем, кому он решит отправить ссылку. Не превращать его в бессодержательный каталог книг и пустых карточек.

Проверка ценности: может ли пользователь после урока **объяснить механизм своими словами, проверить аргументы, решить новую задачу и вернуться к нему спустя время**. Просмотры страниц, проценты и число прочитанных глав сами по себе недостаточны.

**Восемь направлений:** бизнес и стратегическое мышление, психология, наука, технологии и искусственный интеллект, здоровье и продуктивность, финансы, философия, история. Новые направления возможны, если реально полезны. На сегодня не считать их все наполненными материалами.

**Пожелания владельца:** живой разговорный русский язык, примеры и аналогии, инициативность ассистента, аргументированная критика, проверка фактов. Для обучения три глубины: «Быстро понять», «Разобраться», «До глубины» (на текущем сайте некоторые подписи отличаются). В новом интерфейсе разрешённый термин для разбора возражений: **«Проверка аргументов»**. Не использовать прежнее отвергнутое владельцем название.

### 5.2. Учебный контент
- Три подготовленных авторских урока на базе конспекта книги о социальных связях: темы **доверия и деловых обязательств**, **социальных связей и полезной сети контактов**, **личных границ и рабочих ролей** (идентификаторы `trust`, `network`, `boundaries`).
- Для каждого три уровня глубины, учебный кейс с объяснением, ссылки и ограничения; часть ссылок добавлена из независимой научной библиографии.
- Раздел книги показывает 18 тематических частей **19-страничного конспекта**, а не всю первоисточную книгу. Это вторичный материал, не прямая расшифровка оригинала.
- `learning-v12.js` добавил открытый вопрос по каждому уроку, текст ответа не менее 80 символов, критерии самостоятельной сверки и отдельную запись самопроверки **после правильного ответа на базовый кейс**. Это не автоматическая оценка качества произвольного текста.

### 5.3. Практика и мышление
- Бизнес-лаборатория: три **вымышленных**, явно обучающих ситуации: партнёрство/перевод 300 000 ₽, друг в команде, поставщик с громким именем. У каждого варианты и разбор причин, рисков и ограничений.
- «Проверка аргументов»: тезис, сильное возражение, что проверить и указание источника/статуса. Цель — точность, а не искусственное равенство любых мнений.
- Начальная карта знаний: **связанные карточки и переходы**, пока НЕ полноценный редактируемый граф с типизированными рёбрами.
- Дополнительное интервальное повторение на основе самостоятельных отметок с эвристическими интервалами 1, 3, 7, 14, 30 дней. Не считать эту модель клинически или научно оптимизированной.

### 5.4. Личные функции и аудио
- Локальное сохранение прочитанного, задач, заметок, закладок, результатов самопроверки и тренировок. Отметка **«Прочитано»** не выдаётся за объективное освоение знаний.
- Экспорт/импорт прогресса в JSON; данные добавочного модуля входят в `extensions`.
- Аудиостудия работает с аудиофайлом, который пользователь выбирает на своём устройстве. Постоянный плеер остаётся при переходе между разделами, сохраняет скорость и позицию прослушивания. После обновления страницы MP3 требуется выбрать снова (сам файл не хранится в облаке).
- Прогресс зависит от конкретного браузера/устройства. Нет учётной записи, серверной синхронизации и восстановления «по логину».

## 7. Фактическая архитектура и тесты

**Технологии сейчас:** статический HTML/CSS/JavaScript без серверного рендеринга и без необходимости Next.js для запуска. GitHub Pages отдаёт сайт из ветки `main` через GitHub Actions. На v1.2 основные файлы:

- `index.html`: HTML, CSS, основной маршрутизатор/учебные данные, базовые функции и интерфейс. Монолитный файл около 70 тыс. символов в HTTP-ответе.
- `learning-v12.js`: отдельный JS-модуль новых образовательных функций, около 21 тыс. символов по HTTP.
- `scripts/verify-site.mjs`: структурные проверки данных уроков, синтаксиса JS и ключевых модулей.
- `tests/browser-smoke.mjs`: функциональные Chromium-тесты 320/390/768/1440 px, навигация, отсутствие переполнения, автономное аудио, ответы, кейсы, сохранение данных.
- `.github/workflows/pages.yml`: PR-валидация, публикация `main`, GitHub Pages, проверка внешнего HTTPS. Действия обновлены до Node 24; runner закреплён на Ubuntu 24.04 в этой редакции.
- `scripts/verify-public-site.py`: запросы к опубликованному адресу, HTTP 200 и фактическое содержимое HTML + `learning-v12.js`.

**Локальные состояния:** базовый ключ `samorazvitie_site_v1`, отдельный ключ `samorazvitie_learning_v12`. При рефакторинге нужна миграция/совместимость, нельзя тихо обнулять данные. Экспорт/импорт JSON должен сохранять оба набора.

**Права:** static Pages не может безопасно хранить API-ключи, обслуживать приватные аккаунты, вызывать защищённые платные ИИ-сервисы на сервере или синхронизировать прогресс самостоятельно. Для этих функций потребуется отдельная серверная часть и согласование инфраструктуры.

**Исправлено и проверено в v1.2:** горизонтальное переполнение страницы книги на ширине 320 px; сброс аудио при переходе из книги в урок; ложная метка «Освоен» для просто прочитанного; отсутствие более глубокого открытого задания; старые предупреждения Node 20 в workflow; отсутствие функционального теста настоящего браузера; разрыв между «публикуется» и «отдаёт HTTP 200». Технический аудит размещён в `docs/AUDIT_2026-11-15.md`.

**Открытые ограничения / технический долг:**
1. Монолитный `index.html` содержит встроенные CSS/JS/учебные данные; дальнейшее расширение усложнит тестирование и редактуру. Нужен пошаговый вынос данных в независимые файлы без поломки существующих hash-маршрутов и прогресса.
2. В проекте существуют простые базовые повторения и отдельное расширенное расписание, их стоит свести к одной предсказуемой модели с прозрачными статусами.
3. Самопроверка свободного ответа не умеет оценивать смысл; требование 80+ символов не равно пониманию. Нельзя объявлять её объективным экзаменом.
4. Недостаточная глубина источников в части учебных тезисов; всё ещё нужен аудит утверждений, сопоставление культурных обобщений с данными, точные цитаты из доступного оригинала и период ревизии материалов.
5. Карта знаний пока карточная, без типизированного графа и пользовательского маршрута.
6. Аудио без полной транскрипции, привязки таймкодов к главам и полноценной возобновляемости файла после перезагрузки.
7. Локальные заметки уязвимы к очистке браузера/смене устройства; пока спасает только экспорт JSON.
8. Сайт публичен для любого обладателя ссылки, авторизации по приглашениям нет. Нельзя считать `noindex` механизмом приватности.
9. Полноценный ИИ внутри сайта не существует, расходы на сервер/API не согласованы.
10. Вариативных заданий и глубокого авторского курса пока мало; число готовых уроков не эквивалентно полному разбору 18 частей конспекта.

**Понимание:** режим «Я не понял», который объясняет иначе, использует аналогии и уточнения, проверяет новый результат, а не просто повторяет текст. Личные маршруты к конкретной цели, компетенции и контрольные точки.

**Карта знаний:** понятия/книги/авторы/теории/исследования с типами связи, связанными заданиями и осмысленной навигацией. Не делать декоративную схему ради красоты.

**Персонализация и организация:** полнотекстовый поиск, качественная библиотека восьми направлений, заметки, закладки, выделения, история ошибок, контрольные вопросы, прогресс, экспорт и резервное копирование, размер шрифта, удобный режим чтения, доступность с клавиатуры, тёмная/светлая темы, мобильный UX, PWA когда реально полезен.

**ИИ-агент:** собственный помощник внутри сайта, способный по запросу искать материалы, исследовать тему, проверять утверждения с источниками, объяснять иначе, создавать и проверять задания, предлагать повторения, связывать понятия, готовить черновики новых уроков. Один контролируемый серверный агент на старте; расходы, секреты, права и логи. Публикации, удаление, изменение кода и платные действия — только с утверждением владельца.

**Профессиональная разработка:** актуальная документация, ветки/PR, CI, проверка живой ссылки, сохранность пользовательских данных, реальный результат после каждого выпуска. Разделять: предложено / написано / проверено / размещено.

## 11. Обязательная процедура после КАЖДОГО крупного обновления

Это **новое прямое требование владельца**, обязательное для всех будущих чатов.

1. **Сверить факты:** прочитать живой `main`, PR, успешный workflow, по возможности логи реального HTTP-теста. Если нет подтверждения — не писать «опубликовано».
2. **Обновить GitHub-документы:** `PROJECT.md`, `ARCHITECTURE.md`, `ROADMAP.md`, `DECISIONS.md`, `CONTENT_GUIDE.md`, `PROGRESS.md` и нужные отчёты `docs/` со статусом «сделано / не сделано / проверить».
3. **Подготовить пользователю новую ПОЛНУЮ версию `PROJECT_CONTEXT_CURRENT.md`**, а не короткий список изменений. Вставить: дату, версию, URL, commit/PR/CI, работающие функции, архитектуру, настройки доступа и хранения, изменения в учебном содержании, источники и статус проверки, исправленные/открытые проблемы, техдолг, все согласованные и новые идеи, подробную дорожную карту, критерии готовности и точный первый шаг следующего чата.
4. **Не терять историю важных решений:** не переписывать молча принятые ограничения; переносить незавершённые идеи и помечать отложенные функции.
5. **Дать два способа получить отчёт:** файл `.md` для добавления в «Источники» и обычную ссылку на Markdown в GitHub (когда размещение документа согласовано). Если ссылка на файл в чате не открывается, предложить копируемое содержимое.
6. **Явно попросить заменить старый файл `PROJECT_CONTEXT_CURRENT.md` в источниках проекта вручную.** Не утверждать, что источники обновились сами.
7. **Дать готовое сообщение для нового чата**, чтобы помощник сначала прочёл спецификацию, актуальный контекст и GitHub, а потом продолжил следующую задачу.

При небольшом багфиксе можно обновить только профильные GitHub-файлы, но при выпуске новой версии, крупной архитектурной работе или значимом изменении обучающей методики этот полный отчёт обязателен даже без напоминания пользователя.
